对团队leader的一些建议

2020年7月15日 · 3 分钟 · zgia

01，leader其实是一件苦差事，尤其对创业公司来说。它不但要求我们想的多，做的多，还得承担更大的责任

02，leader是别人对自己的一种期望：既要技术出众，又要团队带得好，当一些客观因素存在时，它便成为一种压力

03，做一名好的leader，要能学会转化这种压力，可以向下让团队成员分担，也要向上让leader的上级分担

04，所以，leader最重要的一个特质就是，人尽其用：让合适的人做合适的事情（思考一下：团队成员协助leader完成任务，所有人都是为公司做事的，发薪水是公司，但是管理者是leader，leader决定他的薪水多少和是否会涨薪，leader的leader决定他的薪水多少和是否会涨薪，这是一个递归。）

05，而为了达到目标，需要准确的理解每个需求，并精确的分解，以便分配给合适的人

06，这要求leader务必了解整个系统，但是当时间不允许（加入团队时间不足）怎么办？就需要求助/依赖老同事——这也是所有公司老员工的一个非常重要的价值：信息传递——这时最忌讳碍于面子或者其他因素，自己一个人硬顶上：由于讨论双方对功能了解的不对称，会带来沟通上的偏差，信息传达就不会全面，最终导致目标的错位

07，需求来了，leader和团队成员去评审这个需求，评审完，所有人都要想一想：

  1. 还有哪里没有考虑到的？
  2. 设计上是否有不足？
  3. 还有没有相关干系人没有沟通好？
  4. 信息是否了解完全？
  5. 有没有风险？有没有相应的风险应对措施？
  6. 重要的一点是，发挥参与的团队成员的主动性，让TA们提出异议，提出反对意见——尤其当新leader时，这点更为重要——所有的问题都代表了他们的思考。leader收集这些意见和建议，分析并采纳或者拒绝。思考的外延越广，行动的路径越平缓，那么结果就越完善

08，检验讨论需求时的参与度的一个重要指标，就是看当事人能不能提出问题，提出有见解的问题

09，认真面对每一个需求，无论是这个需求是复杂、琐碎，甚或简单，都要有思考，切勿有遗漏

10，咱们每个人加入到一个公司，一方面是为了工资，另一方面是为了能做点儿什么——当然不排除有些人只为了工资。但是当TA愿意接下leader这个职位/或者接下一份复杂的需求时，那么TA一定是想有所作为

11，既然想有所作为，那么就得经常思考：

  1. 我怎么才能做的最好？
  2. 我这么做，是否做到了最好？
  3. 我没有做好，是什么原因导致——同样的问题，以后如何避免？
  4. 我的每份邮件、汇报，或者每次在线沟通，是否能理解对方的真实需求？是否完整、准确的表达了我的想法？对方接收到后，会如何理解？

12，leader还要经常问自己，领导对自己不满意，是什么原因？

  1. 是TA吹毛求疵了？
  2. 是TA不近人情了？
  3. 还是自己没有达到要求——领导的要求是什么？
  4. 切记：领导不会无的放矢

13，以上那么多，其实可以归纳成一句话：我怎么才能做的更好？
